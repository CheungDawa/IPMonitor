# ADR 0003: 驾驶舱展示门户与运维管理后台双门户解耦架构

## 状态
已接受 (Accepted)

## 上下文
前期版本将监控大屏、设备台账、告警配置、系统设置等全部组织在同一个中后台管理侧边栏中。
但在实际使用场景中：
1. **监控驾驶舱 (Cockpit)**：主要用于投屏、大屏巡检、NOC 态势感知与无人值守监控，需要沉浸式、高信息密度、全屏可视、免干扰；甚至需要支持免登录公开大屏展示模式。
2. **运维管理后台 (Admin Console)**：主要用于管理员进行资产录入、双模式地图选点、分组保护、导入预检、通知渠道配置与系统热备份，需要标准的中后台表单与表格交互，具备严格鉴权。

将二者混在一起会导致驾驶舱受制于侧边栏框架，无法达到真正的“态势感知驾驶舱”体验；同时管理后台的专业性也被稀释。

## 决策
1. **前端双门户解耦 (Dual-Portal)**：
   - 驾驶舱路由 (`/` 或 `/cockpit`)：采用独立的 `CockpitLayout`，全屏无侧栏，以地图和核心遥测数据为中枢，包含实时告警跳动流水、时延折线图与健康度矩阵。
   - 管理后台路由 (`/admin/*`)：采用经典的 `AdminLayout`，提供标准的左侧导航栏、设备台账、双模式选点、分组维护、Excel 导入预检中心、告警配置与系统备份。
2. **双向互通入口**：
   - 驾驶舱右上角常驻显著按钮：“⚙️ 进入管理后台”；
   - 管理后台顶部常驻显著按钮：“🚀 切换至监控驾驶舱”。
3. **数据接口解耦优化**：
   - 针对驾驶舱高频巡检刷新需求，后端提供专用的聚合只读接口 `/api/v1/cockpit/overview`，单次网络请求聚合大屏全部指标与点位，减轻客户端与数据库开销。
   - 管理后台沿用细粒度 RESTful API 进行事务操作。

## 后果
- 驾驶舱视觉体验极大提升，达到专业 NOC 态势感知效果；
- 管理后台操作更聚焦、更专业；
- 架构层次更加清晰，便于未来分别扩展驾驶舱主题或管理权限。
